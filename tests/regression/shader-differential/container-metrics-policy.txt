Shader Differential Container Metrics Policy

The instruction_count and register_count metrics are read from the emitted Cg
containers. They are not recomputed from decoded instructions by the harness.

container-metrics-baseline.csv is the gate trigger. When it is present beside
stage-differential.ps1, staging reports SDIFF-METRICS-GATE and fails by default
if any row has a larger instruction_delta or register_delta than its matching
baseline row. The match key is role, name, profile, source, and uniform_set.

Use -MetricsReportOnly for explicit investigative runs that should print the
same gate line without failing the stage. New rows missing from the baseline
are reported as missing_baseline_rows and do not fail by themselves; accepting
new rows should update the baseline in the same reviewed change.

The role=reference baseline rows are cost protection for the curated durable
reference-pair stage. They are not corpus-wide cost coverage; broader corpus
cost policy lives in the reference-corpus and reference-tree-corpus roles.
As recorded on 2026-09-05, those 66 rows total 1447 instructions against the
reference's 934, and 266 registers against the reference's 152, with 45 of 66
rows carrying a positive register delta. The baseline records current cost, not
acceptable cost; baseline_regressions=0 means nothing got worse, not that the
cost is acceptable.

If every current row is missing from a present baseline, the gate reports
status=no-coverage instead of status=ok. In fail-by-default mode that fails the
stage, because no baseline row was actually compared.

Any commit that moves an existing baseline row in the worse direction must say
so in its commit message and explain why the higher cost is accepted.

Reviewed, named allowances (opt-in only)

stage-differential.ps1 accepts -MetricsAllowancePath <UTF-8 JSON>. With an empty
path it preserves the existing gate and output. No allowance ships by default.
The caller is responsible for obtaining approval for the named exceptions.

Schema version 1 has exactly two top-level fields:
  { "schema_version": 1, "entries": [ ... ] }
Each entry has exactly these fields:
  role, name, profile, source, uniform_set: exact case-sensitive row identity
  card, reason: nonblank strings (a descriptive card is accepted)
  count: the JSON integer 1 (the CSV key must identify one row)
  historical, current: objects with these six JSON integer fields:
    ours_instruction_count, reference_instruction_count, instruction_delta,
    ours_register_count, reference_register_count, register_delta
Raw counts must be nonnegative and each delta must equal ours minus reference.
The historical object pins the baseline CSV values; current pins staged values.
Counts and deltas must fit signed 32-bit integers. Identity fields cannot contain
the key delimiter '|'. Unknown or missing fields are rejected.
Repeated JSON member names are rejected, including equivalent escaped names.

Each entry must match one actual regression, all five identity fields, and all
twelve metric values. Missing/fixed/improved rows make an entry stale and fail;
growth, changed reference counts, duplicate keys, or malformed files also fail.
An allowance requires a baseline, even with -MetricsReportOnly. Invalid
allowances throw regardless of ReportOnly. A valid partial allowance leaves
unmatched regressions failing in the default enforcing mode.

The original Summary.Status and BaselineRegressions remain visible. The opt-in
result adds EffectiveStatus, AllowedRegressions, UnallowedRegressions,
AllowedKeys, and Allowance (absolute Path and Sha256 of the exact parsed bytes).
EffectiveStatus is allowed only when every raw regression matches an entry;
otherwise it retains the raw status, including no-coverage. Empty entries
waive nothing. SDIFF-METRICS-ALLOWANCE prints the effective verdict and pin.

The stager writes container-metrics-gate.json beside container-metrics.csv
before enforcing the verdict, so a mixed allowed/unallowed failure retains
its evidence. The boot/session consumer must pin the allowance in advance,
record that pin in its session evidence, and call
Assert-ContainerMetricsAllowancePin before every boot, comparing the gate's
pin with the session's expected pin. Metrics allowance is not pixel proof.
