# Object-only TOC low-word witnesses

The checker admits exactly a reference to offset +4 in an eight-byte TOC entry
loaded by `lwz`, either with `TOC16` on r2 or a matched `TOC16_HA` / `TOC16_LO`
pair (`addis rN,r2,...; lwz rD,...(rN)`). Intervening instructions must be known
and must preserve rN. Control flow, unknown instructions, mismatched registers,
and ambiguous relocation sites do not establish a match.

Object-only mode **cannot distinguish a legitimate +4 low-word read from a bad
remap landing at +4 with the same shape**. The linked checker is the gate for
that distinction. A recognized shape is not proof of correct linked addresses.
Counts report semantic accesses separately from relocation sites (two for a
HA/LO pair, one for a direct access).

Recognition checks the linear interval between the two instructions; it does
not establish whole-program control-flow dominance. Each HA is consumed by
at most one LO; a second LO sharing that HA remains flagged conservatively.
Unknown relocation write widths and multiple relocation sections targeting
the same recognition code section cannot establish unchanged instruction bytes.

All original bytes and assembly sources are retained. Replacement negatives
are generated by changing only the code relocation addends, not their symbols,
instructions, entry width, or container identity. Each converted positive has
a corresponding replacement RED.

Additional independently encoded ELF witnesses cover direct r2 access, +2,
`ld` at +4, register mismatch, missing halves, clobbers, branches, unknown
instructions, non-executable sections, duplicate relocations, and archive
members with identical names but different instruction bytes. A lone four-byte
entry at +4 is out of bounds and rejected; +4 at the start of a real next entry
remains valid and is not counted as a low-word read.

Adversarial ELF witnesses also redirect `.rela.toc` to the code section, add
a second relocation section that overwrites the HA, and place an eight-byte
relocation in the preceding instruction so it overlaps the `lwz`. All stay RED.
