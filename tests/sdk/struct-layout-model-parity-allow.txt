#
# Records whose ilp32 and lp64 rows in struct-layout-table.tsv differ (or are
# unpaired), with the one-line reason category the difference falls under.
#
# struct-layout-model-parity-test.py pairs the two rows of every record (spu is
# excluded -- a different data model, not an ilp32/lp64 row), compares
# size/alignment/every member offset, and fails when a differing record is not
# listed here, when a record present in only one model is not listed here, or when
# an entry here matches no record that currently differs (a stale entry), so this
# file cannot quietly outlive the layout differences it was written to justify.
#
# The invariant being guarded: a pointer that crosses the PPU<->lv2, PPU<->SPU,
# or PPU<->system-module boundary (PRX / lv2 / sysutil / sync2) is a 32-bit
# effective address (mode(SI)) even under PPU LP64.  A record that a system
# module reads therefore has to lay out identically in ilp32 and lp64; a record
# in this list has at least one pointer member that violates that rule.  Each
# entry's category names which kind of violation the checker is allowing.
#
# Reason categories (one per line, after the tab):
#   prx-boundary-open - a pointer member of the record would widen from 4 to 8 bytes
#                 under PPU LP64, but the record is read by a system module
#                 (PRX / lv2 / sysutil / sync2) that keeps 32-bit pointers. The
#                 member is missing the 32-bit PRX attribute it needs; layout is
#                 a probable SDK bug. Tracked under card t_849c499c.
#   known-open  - the record is already recorded in struct-layout-known-open.txt
#                 (system-domain / pending), so its layout is tracked there.
#   spu-side    - the record is shared with SPU code; its pointer members are SPU
#                 local-store / 64-bit effective addresses that do not grow under
#                 PPU LP64, so any cross-model delta the PPU checker reports is an
#                 artifact of the SPU-side layout only, not an SDK defect.
#   defect-open - the record is passed between PPU and SPU with its layout
#                 expected identical in ilp32 and lp64, but the SDK header does
#                 not give it that. Carded for a follow-up fix; the reason line
#                 carries the card id.
#
# Each line is: <type fnmatch glob><TAB><category: detail>
# A leading-* glob ("*CellFont") matches both the "CellFont" typedef row and the
# "struct CellFont" tag row that the table carries for some records.
#
